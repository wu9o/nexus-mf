# CSS 生命周期

远程微应用常常会在运行时向 `document.head` 注入 `style` 或 stylesheet。Nexus MF 会按远程运行时记录这些节点，并在最后一个使用该运行时的实例卸载后移除它们。

## 生命周期模型

```text
第一个实例挂载
  → 开始观察 document.head
  → 记录该远程新增的 style/link
第二个实例挂载
  → 共享同一份样式记录
第一个实例卸载
  → 只减少引用计数
最后一个实例卸载
  → 停止观察并移除已记录样式
```

宿主应用原本就存在的样式不会被框架认领或移除。

## 远程应用约定

- 为 class 增加应用前缀，例如 `nexus-dashboard__header`；
- 不要修改或删除宿主已有的 `style`、`link` 节点；
- 动态样式尽量插入 `document.head`；
- 弹窗、Portal 等挂载到 `body` 的组件要单独验证视觉边界；
- CSS Modules 可以继续使用，但它不能替代全局依赖和第三方组件库的边界治理。

## 排查样式残留

1. 卸载微应用后检查 `document.head` 是否还存在对应的 `style` 或 `link`。
2. 检查远程是否把样式插入了 `head` 之外的节点。
3. 检查是否复用了宿主的全局 class 或覆盖了宿主 CSS。
4. 如果同一远程有多个实例，确认最后一个实例卸载后再判断是否残留。
